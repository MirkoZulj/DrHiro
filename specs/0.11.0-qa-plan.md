## 4. Contract-probe checklist (new endpoints)

Per spec §7, every step: contract probes incl. response-shape checks. Probe
each new/changed endpoint on the disposable stack, asserting shape + semantics:

- `GET /medications/intake` — keys `view,start,end,tz,days,items`; days only with doses; `color_idx == int(sha1(item_id)[:4],16) % 8`; `short_name` ≤12 chars at word boundary.
- `POST /medications/intake` — 1..20 entries; 21 → 422; response `{doses, already_logged}`; `scheduled_for IS NULL`.
- `PATCH /medications/doses/{id}` — amount/taken_at/note; 404 cross-tenant.
- `GET /medications/{id}/composition` — scopes unit/day/period; row keys per §3.4; `above_ul`.
- `POST/PATCH /medications` — `create_reminder` accepted+ignored with `warnings`; `pause` → 410; `GET /adherence` → `Deprecation` header.
- `GET /tools/list_nutrient_codes` — catalogue codes + labels + canonical unit; unknown code in `add_medication_item` → 422 with hint.
- `GET /intake/overview|day|nutrients` — §4.6 shapes; `status` enum ok|partial|food_missing|no_data; `dri_version`; `reference_profile.assumed`.
- `POST /system/food-micros/backfill` (admin only; non-admin → 403) + `GET /system/food-micros/status`.
- Agent tools: `log_dose` archived_match/unarchive; `list_doses` days-with-intake-only; `get_my_intake` condensed payload + completeness note <80%.
