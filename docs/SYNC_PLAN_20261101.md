## 2. Root cause

`/opt/drhiro` was never a git repository. Four weeks of in-place editing happened with no version control, so the one release that did reach GitHub (2 Oct) could not be followed.

## 4. Decisions needed before merge

**Repo-only files — did production drop them deliberately?**

| File | Reading |
|---|---|
| `routers/telegram_ingress.py`, `services/telegram_ingress.py`, `services/ingress_keys.py` | Bot now reaches the API through the OpenClaw gateway; ingress keys likely obsolete |
| `routers/settings.py`, `services/settings_store.py`, `views/SystemSettings.tsx` | Settings moved into `app_settings` or dropped |
| `services/consumption.py`, `nutrition_validation.py`, `intelligent_meal_service_patch.py` | Superseded by the production food-resolution / JEV cascade path |
| `schema_activities.py`, `alembic/versions/a0b1c2d3e4f5_activities_table.py` | Production renamed the revision to `…_reconstructed_noop` |
| Migrations `9a1b…`, `a1b2…f7`, `b2f3…`, `c4e5…`, `c9d0…`, `d6e7…`, `e1f2…`, `e7f8…`, `f1a2…` | Never applied in production; the DB reached `a9b8c7d6e5f4` another way |
| Tests `test_account_deletion_purge`, `test_jev_cascade`, `test_settings_store`, `test_tool_write_idempotency`, `test_trends_bucketed_macros` | Coverage for the above; keep only if the code is kept |

Recommended default: **keep the code out, keep the tests only where the feature survived**, and record each deletion in the PR body. Nothing is destroyed — the old repository history still holds every file.

**Migration strategy:** do not merge chains. Production's `alembic_version` = `a9b8c7d6e5f4`. The repository chain is stamped to that revision, the nine unapplied migrations are moved to `alembic/deferred/` (the folder already exists for this purpose), and every future migration branches from `a9b8c7d6e5f4`.
