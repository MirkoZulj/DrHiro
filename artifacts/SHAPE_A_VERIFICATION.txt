## 2. The category split — juice is NOT counted as water, but it is not shown as juice either

Real summary, computed in-process against the deployed API:

```json
{ "water_ml_today": 800,
  "liquids_today": { "total_ml": 800, "water": 500, "juice": 0, "other": 300 },
  "meals_logged_today": 1, "calories_kcal_today": 45.0, "activity_kcal_today": 180.0 }
```

Juice is **not** in `water` (500 only) — the owner's stated condition holds. But the
300 ml is in `other`, not `juice`.

Root cause is upstream, not in the dashboard: the liquid WRITER stored
`category: "non_alcoholic"` for an orange juice. No rearrangement of the
dashboard's category list can turn that into `juice`.

## 3. REGRESSION I INTRODUCED — the web UI reads the LEGACY keys

The deployed bundle `/usr/share/nginx/html/assets/index-C-s2BbhV.js` builds the
water tile breakdown from fixed legacy keys:

```js
breakdown: N.key==="water" && e.liquids_today ? [
  {label:"Water",         ml:e.liquids_today.water},
  {label:"Non-alcoholic", ml:e.liquids_today.non_alcoholic},
  {label:"Beer",          ml:e.liquids_today.beer},
  {label:"Wine",          ml:e.liquids_today.wine},
  {label:"Spirits",       ml:e.liquids_today.spirits},
  {label:"Other alcohol", ml:e.liquids_today.other_alcohol},
].filter(M => M.ml > 0) : void 0
```

The Shape A dashboard change replaced that legacy list with canonical categories
(water, coffee, tea, juice, soda, milk, alcohol, smoothie, broth, other). So:

- `non_alcoholic`, `beer`, `wine`, `spirits`, `other_alcohol` are now **undefined**.
- `.filter(M => M.ml > 0)` drops undefined rows, so the **300 ml juice no longer
  appears in the tile breakdown at all**, even though `total_ml` (800) still
  includes it and the Water row still shows 500.
- Any beer/wine/spirits entry would likewise vanish from the breakdown, since the
  writer's `alcohol` never surfaces under the legacy `beer`/`wine`/`spirits` keys.

Net: the dashboard change is **incompatible with the deployed web image**. It
removed legacy buckets the UI depends on without the UI learning the new keys.

Correct fix (not applied): emit BOTH key sets (superset) from the API, or land the
writer's canonical categories AND the web UI's new keys together. The writer must
also stop storing `non_alcoholic` for a juice.
